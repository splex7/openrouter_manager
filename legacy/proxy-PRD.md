# ClassKeys PRD

## 1. 문서 정보

| 항목 | 내용 |
| --- | --- |
| 상태 | Draft — 구현 전 최종 검토 필요 |
| 제품명 | ClassKeys |
| 목적 | 수업 구성원과 조에 AI 사용 권한·예산·모델 정책을 안전하게 부여하고 운영한다. |
| 배포 원칙 | OCI 등 별도 서버 없이 Cloudflare와 OpenRouter만 사용한다. |

## 2. 문제와 목표

수업에서 OpenRouter API 키를 학생에게 직접 배포하면 키 유출, 재발급 후 예산 초기화, 조 단위 예산 관리 불가, 고비용 모델 사용 통제가 발생한다.

ClassKeys는 API 키가 아니라 **학생 또는 조라는 주체**에 정책과 사용량을 귀속한다. 자격 증명이 유출되거나 재발급되어도 주체의 기간별 사용량과 정책은 유지되어야 한다.

### 성공 기준

- 관리자는 학생·조·조원 편성을 웹에서 관리할 수 있다.
- 학생은 본인과 본인이 속한 조에 허용된 자격 증명과 사용량만 볼 수 있다.
- 개인/조/프로젝트 전체의 정책 및 예산을 넘는 요청은 OpenRouter 호출 전에 차단된다.
- 키 재발급·폐기 후에도 주체의 일/주/월 누적 사용량은 유지된다.
- 허용되지 않은 모델·provider·요청 조건은 호출 전에 차단된다.
- 프롬프트와 응답 원문은 ClassKeys 데이터 저장소와 로그에 남기지 않는다.

## 3. 제품 원칙과 범위

### 확정 원칙

1. 학생은 OpenRouter 계정을 만들거나 OpenRouter 관리 화면에 접근하지 않는다.
2. 학생의 AI 요청은 ClassKeys Worker를 거쳐 OpenRouter로 전달된다. 따라서 OCI에는 AI 트래픽, 프롬프트, 응답이 도달하지 않는다.
3. Worker는 프롬프트를 저장하지 않고 요청을 전달하며, 응답은 버퍼링 없이 스트리밍한다.
4. 평문 자격 증명은 생성 또는 재발급 직후 한 번만 표시한다. DB에는 검증용 해시만 저장한다.
5. 조에는 하나의 공유 평문 키를 배포하지 않는다. 각 조원에게 서로 다른 **조 범위 자격 증명**을 발급하고, 모두 동일한 조 예산을 차감한다.
6. `public/members.tsv`의 명단은 최초 D1 시드일 뿐이며, 운영 중 정본은 D1이다.
7. 사용자는 사전에 일괄 발급한 ID·비밀번호로 로그인하며, 계정은 학번의 학생 정보에 연결한다.
8. 쿼터 기간의 일·주·월 경계는 UTC 기준이다.
9. 학기 전체 프로젝트 캡은 OpenRouter 충전 잔액 중 Master가 지정한 일부 금액이며, 예외 없이 초과할 수 없다.
10. 학생·조·사용량·감사 데이터는 서비스 종료 시까지 보존한다.

### 범위 안

- 학생, 조, 조원 편성 및 편성 이력 관리
- 학생용 개인 자격 증명 및 조 범위 자격 증명 발급·재발급·폐기
- 학생/조/프로젝트 단위의 예산·모델 정책
- 일/주/월 사용량 집계와 요청 전 차단
- 사용량, 정책 변경, 자격 증명 수명주기 감사
- 일반 사용자, 관리자, Master 역할 기반 접근 제어

### 범위 밖

- 학생 OpenRouter 계정 생성·관리
- 프롬프트/응답 전문 저장, 검색 또는 수업 평가
- OpenRouter 크레딧 구매·환불 처리
- 팀 내부의 자격 증명 공유를 위한 평문 키 재조회
- 모델 자체의 품질 평가 또는 자동 모델 추천

## 4. 사용자와 권한

| 역할 | 대상 | 권한 |
| --- | --- | --- |
| 일반 사용자 | 학생 | 본인 프로필, 개인 자격 증명 메타데이터·사용량, 자신이 속한 조의 사용량 및 본인에게 발급된 조 범위 자격 증명만 조회·재발급 요청 |
| 관리자 | 조교·교수 | 학생/조/편성 관리, 자격 증명 발급·폐기·재발급, 정책 설정, 사용량·감사 조회 |
| Master | 서비스 소유자 | 관리자 권한 관리, 전체 프로젝트 캡, OpenRouter Workspace 연결, 시스템 정책 및 비상 차단 |

학생은 다른 학생, 다른 조, OpenRouter 관리 키, 프로젝트 전체 잔액을 볼 수 없다. 관리자는 자신의 권한 범위에서만 정책을 바꾸며, Master만 전체 차단과 관리자 위임을 수행한다.

## 5. 핵심 도메인

### 학생

- 학번은 고유 식별자다.
- 이름, 반, 지도교수, 상태(활성/비활성), 로그인 식별자를 가진다.
- 삭제 대신 비활성화한다. 비활성 학생의 과거 사용량과 감사 이력은 보존한다.

### 조

- 조 이름, 반, 지도교수, 상태를 가진다.
- 조 생성·이름 변경·비활성화가 가능하다.
- 조원 추가·제거는 유효 시각을 가진 이력으로 기록한다.
- 학생의 조 이동은 과거 조의 사용량을 이전하지 않는다.

### 주체(Subject)

정책과 사용량의 귀속 단위다.

- `student`: 개인 자격 증명 사용량을 차감한다.
- `team`: 조 범위 자격 증명 사용량을 차감한다.
- `project`: 모든 요청의 최종 상위 캡이다.

개인 토큰으로 발생한 비용은 학생 주체에만, 조 범위 토큰 비용은 조 주체에만 기록한다. 개인과 조에 동시에 차감하는 기능은 초기 범위에 포함하지 않는다.

### 자격 증명

| 종류 | 소유자 | 용도 |
| --- | --- | --- |
| 개인 범위 토큰 | 학생 | 학생 개인 예산과 모델 정책으로 API 호출 |
| 조 범위 토큰 | 특정 학생 + 조 | 해당 조 예산과 모델 정책으로 API 호출 |
| OpenRouter 추론 키 | ClassKeys Worker | 학생에게 노출하지 않는 Workspace 전용 상위 키 |
| OpenRouter 관리 키 | ClassKeys Worker | 키·Guardrail 등 관리 API 전용. 추론에 사용하지 않음 |

ClassKeys 토큰은 OpenAI 호환 API의 Bearer 토큰으로 사용한다. 사용자는 OpenRouter URL 대신 ClassKeys의 API 기본 URL을 설정한다.

자격 증명은 `active`, `revoked`, `expired` 상태를 가진다. 재발급은 새 토큰을 발급하고 기존 토큰을 즉시 `revoked`로 만든다. 계획된 교체를 위한 유예 발급은 Master 또는 관리자가 명시적으로 선택할 때만 허용한다.

## 6. 기능 요구사항

### FR-1. 학생 명단 관리

- 최초 배포 시 `members.tsv`의 67명 데이터를 D1에 시드한다.
- 관리자는 학생을 추가·수정·비활성화할 수 있다.
- 학번 중복은 허용하지 않는다.
- 일괄 가져오기는 TSV/CSV 형식을 지원하고, 적용 전 추가·수정·오류 건수를 미리 보여 준다.
- 명단 변경은 감사 이력에 남긴다.

### FR-2. 조와 조원 편성

- 관리자는 조를 생성, 수정, 비활성화할 수 있다.
- 관리자는 학생을 조에 추가·제거·이동할 수 있다.
- 조원 변경 전후의 구성과 유효 시각을 보존한다.
- 조 비활성화 시 활성 조 범위 토큰을 즉시 폐기한다.
- 팀별 최소/최대 인원은 Master가 선택적으로 정책화할 수 있다. 기본값은 제한 없음이다.

### FR-3. 인증과 인가

- Master 또는 관리자는 학생 명단에 연결된 로그인 ID와 임시 비밀번호를 일괄 발급할 수 있다.
- 모든 관리 화면과 학생 조회 화면은 로그인 후에만 접근할 수 있다.
- 최초 로그인 시 임시 비밀번호 변경을 요구한다. 관리자는 비밀번호를 알 수 없으며 재설정만 할 수 있다.
- 비밀번호는 안전한 단방향 해시로만 저장한다.
- 로그인한 계정의 학번을 D1 학생 정보에 연결하고, 관리자·Master 계정은 별도 역할로 연결한다.
- Worker는 역할과 리소스 소유권을 매 요청마다 검사한다.
- 학생 API 토큰은 로그인 세션과 별개의 자격 증명이며, API 호출에는 사이트 로그인 쿠키를 요구하지 않는다.

### FR-4. 자격 증명 수명주기

- 관리자는 개인 또는 조 범위 토큰을 발급, 재발급, 즉시 폐기할 수 있다.
- 학생은 본인 개인 토큰과 본인에게 발급된 조 범위 토큰의 이름, 상태, 만료일, 마지막 사용 시각, 사용량을 볼 수 있다.
- 토큰 평문은 발급 결과 화면에서 한 번만 복사할 수 있다. 이후 화면은 토큰 앞부분 일부와 메타데이터만 표시한다.
- 토큰 유출 의심 시 관리자는 해당 토큰만 즉시 폐기하고 같은 주체에 새 토큰을 발급할 수 있다.
- 토큰 교체는 주체의 사용량이나 정책을 초기화하지 않는다.

### FR-5. 정책과 쿼터

정책은 학생, 조 또는 프로젝트에 부여한다. 정책에는 다음을 포함한다.

- 금액 기준 한도(USD): 일별, 주별, 월별 중 하나 이상
- 허용 모델 allowlist
- 허용 provider allowlist(선택)
- 요청당 최대 예상 비용(선택)
- 최대 출력 토큰 및 지원 모달리티 제한(선택)
- 시작·종료 시각과 활성 상태

여러 정책이 적용되면 모든 정책을 만족해야 한다. 즉 금액 한도는 가장 적은 잔여 예산을, 모델/provider는 허용 목록의 교집합을 적용한다.

기간별 집계는 UTC 경계로 계산한다. 기간이 바뀌면 사용 원장은 삭제하지 않고 새 기간의 누적을 시작한다.

### FR-6. 프로젝트 전체 캡

- Master는 OpenRouter 현재 충전 잔액을 조회하고, 그보다 작거나 같은 금액을 **수업 전체 누적 USD 캡**으로 지정할 수 있다.
- 누적 프로젝트 캡은 학기 시작부터 종료까지의 모든 실제 비용 합계에 적용하며, 주기적으로 초기화되지 않는다.
- 프로젝트 캡은 학생·조 정책보다 항상 우선한다.
- 캡 도달 시 모든 ClassKeys 추론 요청을 차단한다.
- 경고 임계값은 정책별로 설정할 수 있으며, 최소 1개 이상 지원한다.
- 동일 시점의 다수 요청이 캡을 넘기지 않도록 요청 전 예산을 원자적으로 예약하고, 완료 후 실제 비용으로 정산한다.
- OpenRouter Workspace 전용 추론 키에도 같은 누적 한도와 `no reset`을 설정한다. 이 키는 수업 기간 중 교체하지 않아 ClassKeys 내부 캡의 독립적인 최종 안전장치가 된다.
- Workspace 기본 Guardrail에는 모델/provider 제한과 일·주·월 운영 한도를 설정해, Worker 오류나 우회 시의 추가 안전장치로 사용한다.
- 프로젝트 캡에 대한 관리자·Master 예외는 제공하지 않는다.

### FR-7. 모델 정책

- Master 또는 관리자는 OpenRouter 모델 목록에서 수업 허용 모델을 선택할 수 있다.
- 초기 정책은 전체 허용이 아니라 명시적 allowlist다.
- 고성능 프론티어 모델은 기본 비허용으로 두며, 정책을 통해서만 허용한다.
- 비활성화되었거나 allowlist 밖인 모델 요청은 OpenRouter에 전달하지 않고 차단 사유를 반환한다.
- 모델 가격·지원 상태 변경에 대비해 관리자 화면에서 목록을 새로고침하고 정책의 더 이상 유효하지 않은 모델을 표시한다.

### FR-8. 사용량과 감사

- 사용량 원장은 요청 시각, 주체, 자격 증명 ID, 모델, provider, 입력/출력 토큰, 실제 비용, 상태, 차단 사유를 기록한다.
- 프롬프트, 응답, Authorization 헤더, 평문 토큰은 어떤 원장이나 로그에도 기록하지 않는다.
- 관리자·Master의 명단, 조 편성, 정책, 발급, 재발급, 폐기, 역할 변경, 비상 차단 행위는 감사 이력에 기록한다.
- 관리자 화면은 학생/조/기간/모델별 사용량, 잔여 예산, 차단 횟수를 조회할 수 있다.
- Worker가 기록한 비용은 OpenRouter 사용량과 정기적으로 대조하여 차이를 표시한다.

### FR-9. 사용량 히트맵 대시보드

- 사용량 대시보드는 시간 구간별 사용 강도를 색상으로 표현하는 히트맵을 제공한다.
- 집계 단위는 일별, 주별, 월별로 전환할 수 있다. 각 셀은 선택된 단위의 실제 비용 합계를 기본값으로 표시한다.
- 지표는 실제 비용(USD), 요청 수, 총 토큰 수 중에서 선택할 수 있다.
- 관리자·Master는 전체, 특정 반, 조, 학생, 모델, provider로 범위를 필터링할 수 있다.
- 학생은 본인 개인 사용량과 본인이 속한 조의 사용량만 히트맵으로 볼 수 있다.
- 셀을 가리키거나 선택하면 해당 기간의 비용, 요청 수, 토큰 수, 주요 모델을 확인할 수 있다.
- 색상 범례는 현재 선택 범위 안의 최대 사용량을 기준으로 계산하며, 0 사용량은 별도 색상으로 표시한다.
- D1에는 원장과 별도로 일 단위 사용량 집계를 유지해 대시보드 조회가 원장 전체 스캔 없이 동작하게 한다.
- 화면에는 데이터 원본의 시간대와 마지막 OpenRouter 동기화 시각을 표시한다.
- 직접 OpenRouter 키의 Activity API와 같은 UTC 일 단위 원장을 기준으로 히트맵을 집계한다.

## 7. 요청 처리 흐름

1. 학생 클라이언트가 ClassKeys API URL과 ClassKeys 토큰으로 OpenAI 호환 요청을 보낸다.
2. Worker가 토큰 해시, 상태, 소유 학생, 개인/조 범위를 검증한다.
3. Worker가 주체 정책, 프로젝트 정책, 모델/provider 정책을 확인한다.
4. Durable Object가 적용 예산에 요청 비용을 원자적으로 예약한다. 초과하면 요청을 즉시 거절한다.
5. Worker가 Workspace 전용 OpenRouter 추론 키로 요청을 전달한다.
6. Worker는 OpenRouter 응답을 저장·변환하지 않고 학생에게 스트리밍한다.
7. 완료 후 실제 비용과 사용량을 D1 원장에 기록하고 예약액을 정산한다. 실패·취소 시 미사용 예약액을 반환한다.

## 8. Cloudflare 및 OpenRouter 아키텍처

| 구성요소 | 책임 |
| --- | --- |
| Workers Static Assets | ClassKeys 웹 UI 제공 |
| Cloudflare Worker | 로그인 세션 검증, 역할 인가, 토큰 검증, 정책 적용, OpenRouter 스트리밍 프록시 |
| D1 | 학생·조·편성 이력·정책·토큰 메타데이터·사용량 원장·감사 이력의 정본 |
| Durable Object | 프로젝트/주체 예산의 동시 요청 직렬화 및 예약 상태 |
| Worker Secrets | OpenRouter 관리 키와 Workspace 추론 키 보관 |
| OpenRouter Workspace | 수업 환경 격리, Workspace Guardrail, 최종 전체 캡과 모델 allowlist |

OpenRouter는 별도 Workspace(`classkeys-<학기>`)로 구성한다. Master는 해당 Workspace에서 다음을 설정한다.

- ClassKeys 전용 추론 키의 수업 전체 누적 한도(`no reset`)
- Workspace 기본 Guardrail의 모델/provider 및 일·주·월 운영 한도
- 허용 모델 및 필요 시 허용 provider
- 관리 API 키와 추론 키의 분리
- 수업 종료 후 Workspace 키 폐기 및 사용량 검토

학생에게 OpenRouter Organization 또는 Workspace 멤버 권한을 주지 않는다.

OpenRouter 충전 잔액은 계정 전체에서 공유될 수 있다. 따라서 ClassKeys의 수업 캡은 **수업이 지정 금액 이상 지출하지 못하게 하는 제한**이지, 해당 금액을 계정 내에서 예약하는 기능은 아니다. 다른 OpenRouter Workspace나 키에서도 같은 충전 잔액을 쓰면, 수업 캡에 도달하기 전에 계정 잔액이 부족해질 수 있다. 수업 예산 가용성을 보장하려면 이 계정을 수업 전용으로 사용하거나 다른 지출을 별도로 제한해야 한다.

## 9. 비기능 및 보안 요구사항

### 보안·개인정보

- OpenRouter 관리 키와 추론 키는 Worker Secret으로만 저장한다.
- ClassKeys 토큰은 강한 난수로 만들고, D1에는 salt 처리된 검증용 해시만 저장한다.
- 평문 토큰, 프롬프트, 응답 본문, Authorization 헤더의 저장·콘솔 로그·분석 전송을 금지한다.
- 정적 사이트와 API는 HTTPS만 허용한다.
- 민감한 관리 작업에는 재인증 또는 Master 권한 확인을 요구한다.
- 토큰 탈취·대량 실패·예산 급증을 경고 이벤트로 기록한다.

### 성능·신뢰성

- 스트리밍 응답을 메모리에 누적하지 않는다.
- 쿼터 판정의 경쟁 조건으로 프로젝트 캡이 초과되지 않아야 한다.
- OpenRouter 오류·타임아웃·스트림 취소 시 예약 예산을 정산해야 한다.
- OpenRouter 장애와 정책 차단을 구분해 사용자에게 안전한 오류 메시지를 제공한다.
- D1 데이터는 마이그레이션으로 관리하고, 운영·스테이징 환경을 분리한다.

## 10. 운영 정책

- 관리자는 학생별·조별 일/주/월 한도와 모델 정책을 운영 화면에서 설정한다.
- Master는 수업 시작 전 OpenRouter 잔액을 확인한 후 수업 전체 누적 캡을 지정한다. 캡을 높이는 변경은 현재 잔액을 다시 확인해야 한다.
- ClassKeys의 일/주/월 정책은 OpenRouter 키 reset 및 Activity API와 동일한 UTC 경계로 계산한다.
- 수업 전체 누적 캡에는 예외가 없다. 도달 뒤에는 Master도 요청을 허용할 수 없으며, 새 캡을 명시적으로 설정해야 한다.
- 서비스 종료 시까지 학생·조·정책·사용량·감사 이력을 보존한다. 서비스 종료 시의 내보내기·파기는 별도 운영 절차로 정한다.

## 11. 수용 기준

- 관리자가 새 학생과 조를 만들고 학생을 조에 배정하면, 해당 학생은 다음 로그인부터 본인 조만 확인할 수 있다.
- 관리자가 조원 한 명에게 조 범위 토큰을 재발급해도 다른 조원의 토큰과 조의 사용 누적은 유지된다.
- 개인 범위 토큰은 개인 한도 초과 시, 조 범위 토큰은 조 한도 초과 시 각각 거절된다.
- 수업 전체 누적 캡 도달 후 개인·조 범위의 모든 신규 추론 요청이 OpenRouter 호출 전에 거절된다.
- allowlist 밖의 프론티어 모델 요청이 거절되고 감사/사용량 화면에 차단 사유가 표시된다.
- 일반 사용자가 다른 학생, 다른 조, 관리자 API, Master 설정을 조회·변경할 수 없다.
- D1과 Worker 로그에서 프롬프트, 응답 전문, 평문 토큰을 찾을 수 없다.
- 관리자는 일/주/월 전환, 지표 선택, 학생·조·모델 필터를 사용해 사용량 히트맵을 조회할 수 있다.
- 학생은 본인과 본인 조의 히트맵만 볼 수 있고, 다른 주체의 데이터는 응답에 포함되지 않는다.
